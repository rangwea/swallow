# 第二期：整站发布中心与发布状态

日期：2026-10-23。基线：第一期提交 `3391bd0`。

本文整理已确认的产品方案，供用户审阅。当前仅提交设计，不代表功能已经实现，也不授权真实网站发布。

## 1. 已确认的决定与范围

Swallow 面向个人写作与博客发布。第二期采用整站发布：发布全部正式保存的站点内容，独立草稿始终排除。发布前展示变化，发布时冻结内容，失败可追踪并重试，每个部署目标有独立成功基线。

包含：文章发布状态、发布确认面板、后台发布任务、阶段进度、失败详情、重试、历史记录、网站入口、部署器必要修复。

不包含：选择文章发布、定时发布、多站点、协同编辑、自动发布、远程内容编辑、完整远端版本回滚。对象存储上传不承诺原子切换，Git 推送成功也不等同于托管网站已完成构建和刷新。

第一期的独立草稿、恢复和回收站保持原语义。第二期不能在发布时自动把草稿保存成正式文章。

## 2. 仓库依据与实现边界

| 当前实现 | 已确认事实 | 第二期需要改变的部分 |
|---|---|---|
| `backend/app.go:SiteDeploy` | 同步构建并调用部署器，只返回最终结果 | 改为启动持久化任务并返回任务 ID |
| `backend/hugo_engine.go` | 从活动站点构建，成功后切换预览 public | 增加从冻结输入构建到任务专用产物目录的能力 |
| `backend/deploys.go` | 以反射创建配置指针，接口没有任务上下文或进度 | 统一配置类型，增加上下文、阶段事件和结果凭据 |
| GitHub、Netlify 部署器 | 按值断言配置，与统一调用传入指针不一致 | 修复 panic 风险并覆盖回归测试 |
| COS 部署器 | 远端列表未处理分页，存在删除远端多余文件逻辑 | 完整列举并依据管理清单删除 |
| OSS 部署器 | 一处远端元数据读取失败返回 nil，同样会删除多余文件 | 正确返回错误并限定清理范围 |
| 第一期间持久化 | SQLite 保存文章索引，草稿与回收站位于站点外 | 复用数据库和文件持久化方式，不把发布文件放入站点输入 |

本文关于第三方服务的核对、取消、进度能力是接口要求；具体 SDK 可用性在实现前通过依赖源码和适配测试确认。不可因为界面需要就假定服务支持这些能力。

## 3. 发布目标身份与文章状态

### 3.1 每个目标有独立身份

身份由部署类型和实际目的地组成：Git 为仓库与发布分支；Netlify 为 Site ID；COS/OSS 为服务端点、桶及发布前缀。地址采用规范化形式，避免同一目的地因 URL 写法不同产生两个基线。仓库 URL 中的凭证不得进入身份或日志。

修改 Token、密钥等凭证不改变身份。修改目的地或发布分支会产生新身份，旧目标的历史仍可查看。目标显示名称、网站 URL 不参与身份计算；网站 URL 由用户配置，不能根据仓库地址猜测。

发布面板明确显示当前目标，首页文章状态均相对于当前目标展示。切换目标立即重新计算状态。

### 3.2 状态规则

| 状态 | 规则 |
|---|---|
| 发布状态未知 | 该目标尚无客户端确认成功的发布基线 |
| 未发布 | 已有成功基线，但当前文章不在基线的正式文章清单中 |
| 已发布 | 当前文章与基线中的内容哈希相同 |
| 有修改 | 当前文章存在，内容哈希与基线不同 |
| 待下线 | 基线包含文章，但当前正式文章已不在站点内容中 |

成功首次发布前不将存量文章武断标记为“从未上线”。待下线文章主要在发布确认和发布中心展示；回收站中可以显示同一提示。

独立草稿是叠加提示，如“已发布 · 有本地草稿”，不改变发布状态。正文和 front matter 均参与正式文章哈希；图片、主题或站点配置变化单独列为站点变化，不必把所有文章都改成“有修改”。

基线记录本客户端确认成功的发布，不证明远端从未被其他工具修改。未来文章处于 Hugo 排除规则（如 draft、未来日期）时，确认面板需明确“本次构建排除”，不能仅凭本地存在就声称页面已上线。

## 4. 发布中心交互

### 4.1 入口与布局

沿用首页紧凑固定 header，并预留 macOS 窗口按钮安全区域。首页发布按钮打开确认面板；发布中心可查看任务、历史和目标网站。不会用可拖拽悬浮工具栏替代首页布局。

运行中，首页发布入口显示简洁状态，例如“正在上传”；再次点击打开当前任务，不重复创建发布。进入编辑器或设置不会中断后台任务。

### 4.2 确认面板

点击发布先准备冻结快照；准备期间显示实际阶段和错误。快照完成后展示：

- 目标类型、规范化目的地和网站入口。
- 首次发布的“发布状态未知”说明，或相对成功基线的变化摘要。
- 新增、修改、待下线的文章；每类可展开查看标题与路径。
- 主题、配置、本地图片等资源的新增、修改与删除数量。
- 独立草稿数量以及“不包含在本次发布中”的提示。
- 本次范围的快照时间；按钮为“发布整站”“刷新内容”“取消”。

清单绑定准备完成的快照 ID。确认期间再保存文章，不自动替换快照；提示“存在更新内容”，用户可刷新，或明确继续发布当前快照。点击发布时发现源内容已更新但尚未展示提示，也必须再次明确告知，不能静默发布旧内容。只有草稿变化时不提示正式内容更新。

无变化时显示“与上次发布一致”，仍允许显式重新部署；不自动创建任务。准备失败、目标未配置或无法冻结依赖时，发布按钮不可用并给出原因。

### 4.3 任务详情与历史

任务详情展示：目标、快照时间、开始时间、已用时间、当前阶段、变化摘要、阶段日志及失败操作。默认只展开关键错误，详细日志按需打开。

阶段为准备快照、构建、上传、记录结果。只有可靠的总量可得时展示数值进度：例如“已上传 12/40 个文件”；Git/Netlify 无可信总量时展示阶段和耗时，不拼接虚假总百分比。删除旧托管文件属于上传阶段，必须计入结果。

成功后提供“打开网站”和“查看记录”。上传已被服务接收但网站仍需远端处理时显示准确说明，不宣称网页已即时可见。

历史按时间倒序展示目标、时间和结果。可筛选目标，进入任务详情。失败任务提供“重试原快照”“重新准备当前内容”；这两个动作必须明确区分。

界面中英文均可用。进度更新不持续弹 toast，错误不得仅依赖短暂通知。

## 5. 快照、构建与并发

源站点仍是正式内容的事实来源。准备时复制配置、正式文章、主题及本地资源到 `~/.swallow/releases/<releaseId>/source`，生成逐文件路径、SHA-256 与大小清单。排除 public、构建缓存、版本控制目录、草稿、回收站、日志和内部操作记录。

准备与应用内正式保存、删除、恢复、配置写入协调，避免在一次文件修改中间复制。对外部编辑，通过复制前后的文件集合与哈希验证稳定性；源集合变化则重试准备，连续三次不稳定时报告并让用户重试。没有外部文件系统事务，因此不承诺对持续外部写入提供原子文件系统快照。

持久化配置中的绝对 workingDir 不能使构建重新读取活动站点；构建时强制指向快照目录。主题挂载或依赖若指向站点外部，需纳入快照并固定引用；本期实现无法冻结的依赖应在确认前报告，不静默从活动路径读取。远程资源可能改变构建结果，首次构建后的完整产物是上传重试的依据，不承诺重新构建能得到逐字节相同结果。

构建产物放在任务专用 `output`，完成后生成产物清单并标记可上传。发布不使用预览的可变 public 目录；预览也不能修改发布任务的产物。Git 工作目录等部署元数据放在任务专用工作区，不混入静态文件清单。

全应用同一时间只执行一个发布任务，暂不提供排队。对重复点击使用请求幂等键，返回已有任务。准备完成、尚待确认的记录不占用后台执行槽；启动前再次检查执行槽与目标基线是否已变化。若基线变化则重新生成差异摘要并重新确认。

用户可以继续写作。开始后保存的文章进入下一次发布，不能改变当前任务。退出应用时先提示有发布任务；选择等待则不退出，选择退出则请求尽可能停止并保留可恢复记录，不伪造“已撤销远端修改”。第一期编辑器的草稿落盘保护仍需同时满足。

## 6. 任务状态与失败恢复

持久化状态与界面阶段分开，状态至少包含：

| 状态 | 含义及后续动作 |
|---|---|
| preparing | 正在冻结输入；重启后不自动继续，重新准备 |
| ready | 已准备并等待确认；确认前校验快照完整性 |
| building | 正在构建；重启后标记 interrupted |
| uploading | 正在发送或清理远端文件；异常退出后远端可能部分更新 |
| recording | 正在写结果及更新基线；重启时根据持久化结果恢复 |
| succeeded | 发布操作已确认成功，成功基线已提交 |
| failed | 收到确定的错误；基线不更新 |
| interrupted | 任务被异常中断，不能据此推断远端完全未变 |
| outcome_unknown | 远端是否接收本次结果无法确认，需核对 |
| cancelled | 已停止后续操作；若已开始上传，保留远端可能变化说明 |

状态转换和关键阶段事件均落盘。启动后扫描非终态任务，但不自动再次上传。

### 6.1 重试规则

重试创建新任务，关联原任务 ID，复用原冻结内容。有完整产物时复用同一产物；没有完整产物时从原 source 重新构建并生成新的产物清单。原 source 或 output 已缺失、校验失败时禁用对应重试，提示重新准备，不能改用当前内容冒充原快照。

重试读取同一目标的当前凭证。若当前配置指向不同目标，则不允许把原任务重试到新目标；可以恢复原目标配置后重试，或创建新发布。

若该目标已有比原任务更新的成功发布，原任务默认不能直接重试，以免覆盖新内容。界面提示重新准备；本期不将失败重试扩展为历史版本回滚。

### 6.2 远端成功、本地失败与不确定结果

收到服务结果后先持久化结果凭据，再在同一 SQLite 事务中更新任务成功状态和该目标基线。事务失败时保留记录和产物，显示 outcome_unknown，不更新文章状态。

重启或用户点击核对时，优先使用可验证的结果凭据，例如 Git 提交与目标分支引用、Netlify 部署标识；具体核对能力由适配器报告。对象存储只能检查本次清单约定的对象状态，不能据一次请求超时就判断没有写入。

无法核实时继续保持待确认状态；允许明确发起“重新发送原产物”，提示可能重复部署。该动作仍受目标一致性与“无更新成功任务”的限制，不把未知状态自动变成成功。

### 6.3 取消与部分发布

准备阶段可在复制单元间响应取消；构建阶段只有构建器支持停止时显示可执行的取消。不可中断阶段显示“完成当前阶段后停止”。上传适配器须声明是否支持停止请求及其边界。

COS/OSS 文件逐个更新，取消、断网或失败可能留下混合版本。保留已完成操作和计划清单，重试同一产物用于收敛；本期没有跨对象事务，不提供一键自动回滚承诺。出现部分更新时，界面应同时显示“本地基线未更新”和“远端可能已改变”。

## 7. 部署适配器与管理范围

统一适配器约定包括：目标身份、配置验证、任务上下文、上传计划、进度事件、结果凭据、核对能力及取消能力。所有实现遵循一致的配置类型，不依赖不匹配的反射断言。未知类型、分页失败、元数据读取失败和删除失败均必须返回错误。

COS/OSS 完整处理分页。上传清单使用相对路径规范化并禁止路径越出目标前缀。先上传本次文件，最后删除“该目标上次成功清单中存在、本次产物中已移除”的文件。未知远端文件保留，首次发布不自动清理。未知文件与本次计划上传的路径同名时，属于确认的上传覆盖范围；保留未知文件指不额外删除清单外路径。

基线还没有包含、但本客户端中断任务曾上传的文件，以未完成任务清单记录。下次确认时单独展示这些可能残留的文件；只有本地记录可证明来自该目标的客户端任务时，才纳入明确的清理计划，不扩大为全桶同步删除。

Git 使用明确的发布分支和独立工作目录。沿用原实现无条件强制推送不适合可靠重试：实现需检查目标引用，并使用受预期引用约束的更新；不支持该能力时返回冲突，不静默覆盖远端并发变化。仓库或分支变化视为新目标，确认面板始终显示实际分支。

Netlify 记录能够取得的部署结果标识，并按 SDK 实际语义区分“已提交部署”和“可确认的发布完成”。若只能确认接收，界面必须显示该边界。

## 8. 本地数据存储

沿用现有 SQLite，新增带版本号的迁移，不改变第一期草稿与回收站格式。数据结构为逻辑设计，具体字段类型在实现计划中映射。

| 模型 | 关键字段 | 不变量 |
|---|---|---|
| publish_target | id、provider、规范化目的地、display_name、site_url、baseline_run_id | 身份唯一，不含 Token/密钥 |
| release_snapshot | id、source_path、source_manifest_hash、prepared_at、format_version、complete | 只在完整复制并校验后标记 complete |
| publish_run | id、request_key、target_id、snapshot_id、retry_of、state、stage、started_at、finished_at、error_code、error_summary | request_key 唯一；终态不能被迟到事件回退 |
| publish_manifest | run/snapshot 关联、清单类型、文件路径、内容哈希、大小、文章 ID/标题 | 路径相对且规范化；源清单与产物清单分开 |
| publish_event | run_id、sequence、time、stage、message、completed、total | 序号单调，消息脱敏 |
| publish_receipt | run_id、provider、远端结果标识、确认级别、received_at | 可恢复核对，不包含认证信息 |

SQLite 是任务状态、事件、身份和基线的事实来源。大文件和清单正文可放在 `~/.swallow/releases/<releaseId>/`，数据库记录其位置与摘要；文件完成后再登记可用状态。目录包括 source、output、部署工作区和清单。数据库外文件与数据库不是单一事务，启动时须检测未完成目录及完整性，不把存在目录当成发布成功。

成功任务状态与 baseline_run_id 在同一事务提交；失败、取消、中断和待确认不推进基线。上一成功基线保留，以便比较和解释历史。

日志只保留必要的阶段、路径和错误；URL、请求头及 SDK 错误需脱敏，凭证仍按现有配置读取，不复制到发布历史。快照配置如确实含用户自定义敏感字段，只能本地按用户目录权限保存，不向日志展开配置全文。

### 8.1 历史清理

不自动清理当前成功基线、运行中任务、待确认任务及仍被标记可重试的失败任务。优先复用同一快照，避免每次重试复制完整站点。

发布中心提供显式清理已完成历史产物的入口，展示预计释放空间及受影响记录。删除产物后保留历史摘要，取消对应的原产物重试能力；不能留下可点击但文件已不存在的重试按钮。运行前检查可用空间与写入错误，空间不足时停止本地准备，不启动上传。

## 9. 接口与职责

不把全流程继续塞入 App 或现有 Hugo 单文件。建议分为：发布任务服务、快照/差异服务、持久化仓储、部署适配器及前端发布中心。App 仅提供绑定入口。

| 能力 | 输入与结果 | 主要失败语义 |
|---|---|---|
| 准备发布 | 目标、请求幂等键 → 快照/任务 ID 与差异 | 配置无效、来源不稳定、依赖无法冻结、磁盘不足 |
| 确认执行 | 目标、快照 ID、确认的基线版本 → 运行任务 ID | 快照缺失、内容已变需明确确认、基线过期、已有任务 |
| 查询状态 | 任务 ID → 状态、阶段、进度、事件游标 | 未知任务、记录不可读 |
| 查询历史 | 目标、分页游标 → 历史记录 | 分页参数无效 |
| 重试 | 原任务 ID、请求幂等键 → 新任务 ID | 目标变化、已有更新成功发布、快照缺失 |
| 取消 | 任务 ID → 已取消/请求已受理/阶段不支持 | 不能承诺撤销远端修改 |
| 核对结果 | 任务 ID → 确认结果或仍待确认 | 服务无核对能力、网络错误、远端不匹配 |
| 清理历史产物 | 任务 ID 集合 → 逐项结果 | 受保护任务、运行中、仍被引用 |

Wails 事件只用于及时通知，前端重进页面后以查询结果为准。前端根据任务 ID 与事件序号处理迟到/重复消息。发布服务使用独立后台上下文，不因页面卸载而取消；应用退出按前述规则处理。

## 10. 验收与发布边界

1. 两个不同目标互不污染状态；更新凭证不清空基线，换目的地显示未知状态。
2. 首次发布明确状态未知；第二次可准确区分新增、修改、待下线与资源变化。
3. 独立草稿不进入输入、产物或上传清单；发布前仍明确提示未保存草稿。
4. 确认期间保存新内容不会静默更换本次范围；开始后继续写作不改变任务产物。
5. 重复点击只产生一个任务；同一时间只有一个执行任务，页面切换不取消发布。
6. 构建失败不上传；配置类型错误不 panic；底层读、上传、删除错误不会显示成功。
7. 上传失败或中断后保留旧基线；原快照重试不混入后续编辑；有更新成功任务时拒绝旧任务直接重试。
8. 上传成功而本地事务失败时显示待确认；重启不自动重发，也不错误推进文章状态。
9. COS/OSS 超过一页的对象仍能处理；未知远端文件不被额外删除，删除只限已确认管理计划。
10. 缺失/损坏快照、磁盘不足、取消不支持、日志脱敏和历史清理均有可读结果。
11. Git 远端引用冲突拒绝静默覆盖；Netlify 的接收和完成语义与适配器能力一致。
12. 中英文、紧凑 header、macOS 安全区域、键盘操作及关闭时草稿保护通过交互验收。

测试优先使用临时 SQLite、临时站点、可注入故障的假部署器和本地协议测试，不使用真实凭证。真实云端验收需另行指定测试目标并授权，不以正式博客试错。完成后再执行 macOS 打包与应用检查；其他平台由相应构建和验收确认。
