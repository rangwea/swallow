# 第一期：独立草稿、恢复与回收站

## 已确认的方向与范围

Swallow 定位为个人写作与博客发布客户端。本期优先保护写作内容；用户已选择自动保存到独立草稿，正式文章仍需手动保存。本期还包含回收站、部署错误传递修复，以及前后端分页一致性修复。文章历史版本、发布状态和发布中心留到后续，不将自动草稿当成历史版本系统。

基线为 v1.4.0 / 1b4bdd0，开发分支 codex/writing-protection。以下为待用户审阅的具体设计，不代表已经实现。

## 独立草稿

草稿保存于 ~/.swallow/drafts，位于 Hugo 站点内容目录之外。每份草稿含版本号、唯一草稿 ID、关联文章 ID（新文章可为空）、标题、元数据、正文、保存时间及正式文章的基线摘要。文件使用临时文件与重命名写入；正文和元数据作为完整快照保存。

已有文章按文章 ID 找到对应草稿；新文章各自分配草稿 ID，避免多份未命名文章互相覆盖。新文章手动保存后，草稿关联新生成的正式文章 ID。about 页面也使用相同保护机制。

输入停止约 1 秒后保存独立草稿。保存请求串行执行并合并待保存快照，旧响应不能覆盖新内容。标题、正文、标签与日期修改均触发；中文输入法组合期间不执行快照保存，组合结束后重新计时。加载或恢复内容不误触发保存。

编辑器展示“草稿保存中 / 草稿已保存 / 草稿保存失败”，与正式文章的未保存状态区分。失败后保留当前编辑内容并允许重试；不能显示虚假的成功状态。草稿内容不进入 Hugo Build 或部署流程。

手动保存使用点击时的完整快照。成功后，仅当此时没有更新的编辑，才清除该快照对应的草稿并标记正式文章已保存；保存期间继续输入的内容仍作为草稿保留。正式文章写入失败时保留草稿，并报告错误。草稿清除与保存通过相同队列协调，避免迟到的草稿请求重新创建已清除的旧快照。

## 恢复与离开保护

打开已有文章时读取正式文章及关联草稿。草稿内容与正式文章相同则清理冗余草稿；不同则展示恢复提示，提供恢复、稍后处理、明确丢弃。若正式文章自草稿创建后被外部修改，提示冲突，不静默替换正式文章。

首页增加低干扰的草稿入口，能列出并恢复未命名文章及已有文章的草稿。启动后只提示有可恢复草稿，不自动将其写入正式文章。用户丢弃草稿不影响正式文章。

离开编辑器时立即尝试保存最新草稿，成功后可离开；失败则停留，提供重试或明确放弃未持久化内容。窗口关闭与应用退出同样执行保护。关闭过程由 Wails 退出钩子与前端事件握手协调：存在未持久化内容时先阻止退出，收到保存完成确认后再次退出；失败或超时保持窗口开启。已持久化草稿不要求用户额外手动保存正式文章才能退出。

异常退出后的恢复以最后一个成功写入磁盘的草稿为准。由于防抖与磁盘写入时间，不能承诺恢复尚未落盘的最后几个输入字符。

## 回收站

删除文章改为移入 ~/.swallow/trash，存放文章目录、原文章 ID、数据库索引快照、关联草稿和删除时间的清单。与文章关联但位于全局 static/images 的图片本期保留，不自动删除；恢复后引用仍可用。Hugo 内容目录中的文章移出后不会被后续构建发布。

删除先建立可恢复清单，再移动文章，最后删除索引。中途失败必须报告并恢复或保留可识别的恢复记录，不能只删索引并忽略文件错误。批量删除逐项处理，返回逐项结果，已成功项不因其他项失败而丢失记录。

回收站支持查看与恢复；本期不增加永久删除或自动过期清空。恢复优先使用原 ID，目标文章或索引已存在时拒绝覆盖并报告冲突。恢复文章文件与索引后再移除回收站记录；失败保持可重试。需要校验 ID 和清单路径，拒绝路径穿越。

草稿列表与回收站使用与现有紧凑界面一致的入口及列表，不常驻占用正文区域。新增提示支持中文和英文。

## 正式保存与索引一致性

当前 ArticleSave 先写数据库再写 Markdown，失败会导致索引与文件不同步。新增保护需避免放大此问题：串行化文章保存、删除与恢复；通过事务及文件备份处理错误补偿，新文章保存失败不留下幽灵索引，已有文章文件失败不更新索引。正式文章采用完整文件原子替换。

SQLite 和文件系统不能形成真正的单一原子事务。操作日志记录执行阶段，启动时对未完成操作进行恢复；发生无法自动补偿的文件系统错误时保留日志、原文件备份及明确错误，避免宣称操作成功。草稿独立保存，正式保存失败不删除草稿。

## 两处现有问题

Deployers.Deploy 返回底层 Deploy 的实际错误；未知或未配置部署类型返回可读错误，避免空指针。此次不执行真实云端发布测试。

分页以后端返回的有效 pageSize、page 和 total 为准，沿用应用的每页条数配置，校验页码与页大小。搜索条件变化回到第一页；删除最后一页内容后回到有效页。查询参数数量按是否存在搜索条件匹配，查询失败不可被当成空列表。

## 验证与验收

后端使用临时站点及临时 SQLite 验证草稿不会出现在站点内容目录、原子写入、非法 ID、保存后清理、回收站删除恢复、冲突拒绝覆盖及失败补偿。部署使用假实现验证错误传递，不访问真实部署目标。分页验证不同页大小、搜索及边界。

前端验证快速连续输入与保存顺序、中文组合输入、关闭前草稿刷新、保存失败阻止离开、手动保存期间继续输入、新文章恢复、正式文件外部修改冲突和双语提示。重启应用验证磁盘草稿恢复。构建仍需 Hugo Extended；完成后打包并打开应用供实际验收。

本期不自动 commit 或 push 功能代码，除非用户另行要求；本设计文件根据 brainstorming 流程单独提交供审阅。
