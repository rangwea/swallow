# 第一期写作保护

开发分支：`codex/writing-protection`。

输入停止约 1 秒后自动保存独立草稿；正式文章仍需点击保存或按 Cmd/Ctrl+S。草稿位于 `~/.swallow/drafts`，不参与 Hugo 网站构建。首页“草稿与回收站”入口可恢复新文章或已有文章的草稿；检测到正式文章已变化时，会先提示冲突。

离开编辑器或退出应用时，会尝试把最新修改写入草稿。写入失败会停留并提供重试、继续编辑或明确放弃未落盘内容的选择。异常退出后，以最后一次成功落盘的草稿为准；输入防抖期间的最后几个字符可能尚未保存。恢复草稿不会立即覆盖正式文章。

删除文章会将内容及关联草稿移入 `~/.swallow/trash`，可从回收站恢复。恢复时遇到同 ID 的文章或草稿会拒绝覆盖。本期不提供永久删除和自动清空；全局图片文件保留。

正式文章与索引的保存、删除及恢复采用操作日志与失败补偿，日志位于 `~/.swallow/operations`。启动时根据数据库的提交结果完成或撤回未完成操作。无法恢复时报告错误并保留日志，不能把失败当作成功。不要在应用运行期间手动编辑这些内部清单。

同时修复部署器吞掉上传错误、未知部署类型，以及后端每页固定 10 条与界面设置不一致的问题。部署回归使用假实现，不执行真实云端发布。

验证命令：

```sh
go test -race -tags extended ./backend -count=1
go test -tags extended ./... -run '^$'
# 需要可用的 Playwright 与 Chromium 测试运行时，先在 frontend 启动 5174 开发服务。
node frontend/tests/writing-protection.cjs
wails build -tags extended
```

前端测试也可用 `PLAYWRIGHT_MODULE` 指定已安装 Playwright 模块的绝对路径；测试使用独立无头浏览器和模拟后端，不接触实际文章。后端测试使用临时目录和临时 SQLite。
