# 第二期发布中心

功能分支：`codex/publishing-center`。设计见 `docs/superpowers/specs/2026-10-23-publishing-center-design.md`。

首页发布入口现在打开发布中心，不再直接上传。先选择并配置目标，点击“准备发布”生成独立快照，审阅文章与资源变化、草稿排除提示及托管文件范围，再点击“发布整站”。准备期间不会调用远端上传接口。

每个仓库/分支、Netlify Site ID、对象存储桶/前缀有独立成功基线。首次发布状态未知；成功后首页根据正式文件与该基线比较，显示已发布、有修改或未发布，并叠加本地草稿提示。已删除文章在下一次确认清单中显示待下线。

发布任务存储在现有 SQLite 的 `publish_run`、`publish_target`、`publish_manifest`、`publish_event` 表。快照与输出放在 `~/.swallow/releases/<snapshotId>/`。清单和事件分表保存，逐文件进度不重写完整清单。配置 Token 和密钥不进入任务记录；凭证在执行时从对应目标当前配置读取。

发布从冻结 source 构建到独立 output，不复用预览 public。来源在复制前后校验，连续三次仍变化则失败；站点外的模块/挂载或符号链接不能冻结时会停止准备。冻结构建不继承 HUGO_* 配置覆盖，防止回到活动目录读取内容。独立草稿、回收站、生成缓存与版本控制目录排除。

后台任务可查询历史、阶段进度、错误和构建错误位置。数值进度仅在文件总量明确时显示。重试保留原输入及已完成产物；配置目标变化、文件校验不符、已有更新的成功发布时，拒绝直接重试。网络中断后远端可能部分更新，成功基线不会提前推进。

Git 使用明确发布分支和条件引用更新；Netlify 使用可取消的创建/文件上传/状态查询 API，确认 ready 后再记录成功。COS/OSS 都处理分页，只删除前次成功基线或已记录上传尝试所管理、且本次已移除的文件，未知文件保留。部分上传不是原子操作，停止不等于回滚。

应用重启不会自动重发未完成任务。上传/记录阶段中断标记待确认，可以核对具体 Git 引用、Netlify 部署，或对象内容哈希和删除结果。无法核对时允许明确确认后重新发送原产物，不假装成功。发布期间退出会先提示；选择停止退出后等待当前操作响应停止，并继续执行编辑器草稿保护。

可清理历史产物，保留摘要。当前基线、运行中、待确认、待确认执行的快照及仍可重试的任务受到保护；失败/中断/停止记录需先显式放弃重试。共享同一快照的任务共同参与保护判断。

## 验证

- `go test -race -tags extended ./backend -count=1`：冻结与隔离、基线、重试、重启恢复、取消、并发槽、配置隔离、托管清理、本地 Git 租约、COS/OSS 分页及 Netlify 协议测试。
- `go test -tags extended ./... -run '^$'`：完整项目编译。
- 启动 frontend 的 5174 开发服务后，运行 `node frontend/tests/publishing.cjs` 和 `node frontend/tests/writing-protection.cjs`。可用 `PLAYWRIGHT_MODULE` 指定测试运行时。
- `wails build -tags extended`：构建本机应用。

测试使用临时目录、临时 SQLite、本地 HTTP/Git 和模拟部署器，不使用真实云凭证。真实云端/网站发布未在本次自动执行；不同服务的权限、配额、托管侧构建和缓存仍需在指定测试目标上验收。实际网站可能在接收发布后继续处理，客户端成功记录不证明外部工具未修改远端。
